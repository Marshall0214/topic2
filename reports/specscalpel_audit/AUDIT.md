# SpecScalpel 官方仓库审查

日期：2026-10-12。固定版本：`01adb1ed708d410023b8482c52270cac358c8525`。
仓库：https://github.com/HaoyuJi/SpecScalpel 。分支：`analysis/specscalpel-audit`。

## 结论

值得保留为骨架动作分割的离线参照候选，但不宜直接运行默认配置作为我们的独立测试基线，也不宜直接称为在线方法。官方确实提供完整训练逻辑；本次仅完成源码审查、数据清单核对和未训练模型 GPU 前向，没有验证论文精度、完整训练或反向传播。

## 1. 最重要的协议问题：验证清单与测试清单重叠

官方 `csv/PKU-subject/train1.csv`、`val1.csv`、`test1.csv` 分别包含 775、117、234 条序列。逐文件名集合核对结果：

- train∩val=0，train∩test=0，**val∩test=117，即整个验证集包含在测试集中**。
- 官方 train 等于我们现有 train 698 条与 val 77 条的并集；官方 test 与我们 test 234 条完全相同。
- 上述三个清单引用的 feature、label、boundary 文件在现有本地数据根目录均存在。仅验证存在性，不代表逐文件内容、长度和标注已经核对。
- PKU 默认配置 `param_search: True`；`train.py:114` 使用 training 数据，随后以 validation 数据进行选模。文件名虽然叫 `best_test_*`，实际默认选模输入是 val_loader，不能仅依据名字声称直接用 test_loader 选模。

因此，**若按当前公开配置运行，选模会接触测试子集**；若改成 trainval，还会把这 117 条加入训练。两者均不符合我们当前独立测试协议。这是对当前公开文件的判断，不能据此断言作者论文实际运行过程、预训练权重来源或学术行为。

接入时应由我们现有 `configs/dest_compat.json` 生成 698/77/234 清单，不改变原有划分、不合并 trainval；继续保持现有统一选模规则，不能另以测试结果调整轮数或超参。

## 2. 输入、监督和输出

`libs/dataset.py` 将 PKU 原始 T×150 骨架转换为 12×25×T，包含两个人的根关节相对坐标与位移。排列是每个人的位移和相对坐标，不能将我们现有 300 维特征直接 reshape 后当作等价输入。

位移实现 `sample[:,1:]-sample[:,:-1]` 对早一帧使用下一帧信息；在线适配需要另行定义后向差分。训练还有关节遮蔽和随机旋转增广。

除骨架观测外，方法使用预计算 BERT 关节和动作文本嵌入：关节语义图用于模型推理，动作文本用于训练对比损失。应标明“骨架输入、文本先验”，不能宣称完全没有额外先验。训练中的动作片段标签参与特征汇聚，不等于推理依赖真实边界。

训练时返回多阶段类别、边界、对比特征及频域特征；测试返回逐帧类别 logits 和边界 logits。确实是连续动作分割模型，不是仅整段分类模型。

## 3. 原版明确属于离线模型

`libs/models/SpecScalpel.py` 中时间注意力没有因果掩码，频域模块对整段时间轴进行 FFT，空间自适应图也使用时间聚合。默认边界后处理 `libs/postprocess.py` 还对预测边界之间的整个区间做多数投票。这些环节均须考虑未来信息依赖。

可复查的 GPU 实验：固定随机种子 17，用未训练原版模型、1×12×25×160 随机输入与单位关节图，只替换第 80 帧及之后的输入；前 80 帧类别 logits 最大变化为约 0.0156。模型共有 1,505,484 个参数，输出为 1×52×160 和 1×1×160，均为有限数值。这证明该实例输出依赖未来，**不代表训练后精度或实时速度**。

前期探索记录 `runtime_checks.json` 的扰动数值来自另一次未固定模型初始化的运行；正式可复查记录以 `audit_results.json` 和 `scripts/audit_specscalpel.py` 为准。

仅把对称卷积改为因果卷积不足以在线化此模型。当前建议保留原版离线定位，不为增加基线而立即改造整套频域网络。

## 4. 训练可复现性与环境

官方具有训练循环、优化器、损失、多阶段监督、验证、checkpoint 和恢复入口；PKU 默认 300 epochs。提供代码不等于已经完整复现。

当前 dest_gpu 环境（PyTorch 2.8+cu126）成功运行模型前向，但导入官方 train/evaluate/dataset 均因缺少 torchvision 失败。本次没有安装依赖、降级环境、下载数据或权重。官方旧版 requirements 不宜整份覆盖现有可用环境；后续先解决最小依赖兼容。

本地源代码快照有 38 个文件，manifest 记录 SHA256，复核无不一致。仓库中的文本嵌入和权重本次没有下载；这属于本次审查范围限制，不是官方资源缺失。真实数据加载、完整损失、反向传播、恢复训练与精度均尚未通过运行验证。

## 5. 评价口径并不自动与现有实验一致

官方 `libs/metric.py` 的默认背景名字是 `background`；当数据映射中 ID 0 为 `NONE` 时，调用默认 get_segments 会将它作为片段保留。此外最后一个片段结束索引为 T−1，而非我们统一评价的半开区间 T。小数组探针已确认这个行为，不能只因指标同名就直接比较数值。

默认验证还包含预测边界后处理，选模侧重 F1@50；我们的选模规则和原始逐帧评价须保持不变。正式实验应保存 logits、边界与解码标签，统一评价原始输出和后处理输出，并将作者口径作为补充列。论文报告数字不能直接填入我们在线结果的同协议对比表。
