# ProTAS 任务图退化审计

日期：2026-10-12；分支 analysis/protas-task-graph-audit。只读取现有 best/last 权重，干预推理解码；不训练、不读取测试集特征/标签，不改上游或训练实现。具体结果见 results.json。

## 发现

在77条验证序列上，第50轮同一权重结果：

| 推理干预 | Acc | Edit | F1@50 | 背景预测比例 |
| --- | ---: | ---: | ---: | ---: |
| 网络最终分类输出，不做图修正 | 65.82 | 54.21 | 38.71 | 53.30% |
| 当前学得任务图修正 | 43.51 | 8.60 | 3.63 | 97.10% |
| 换回训练开始前的初始任务图 | 65.82 | 54.27 | 38.50 | 53.33% |
| 学得图负数截为0 | 65.82 | 54.21 | 38.71 | 53.30% |
| 仅清零背景行列，保留其他学得参数 | 59.97 | 37.36 | 27.40 | 26.41% |
| 保留学得图，累计进度改为当前进度 | 43.46 | 8.22 | 3.62 | 97.14% |

第25轮也观察到相同方向的变化，程度较轻。审计中的 learned 解码与现有 graph_learner.inference 最大差异为0。

以上是推理干预，不是固定图训练或无图训练结果。raw 仍含进度分支、融合与训练时图损失。负数截断后预测与raw完全相同，说明这项事后干预基本移除了现有图的作用，不能将其宣传为有效的图优化方法。

## 机制与来源

本地 src/baseline.py 的 training_loss 保留官方 TaskGraphLearner.forward 的图损失，系数0.1。上游 model.py 中：

```
status = cummax(clamp(progress,0,1))
penalty = (1-status) @ matrix_pre + status @ matrix_suc
graph_loss = mean(penalty * softmax(class_logits))
corrected_logits = class_logits - eta * penalty
```

对不含正则的图损失部分，任一矩阵元素的梯度是非负权重之和；最小化它会将可学习元素向负方向推。图矩阵本身没有非负约束。官方代码只对 matrix_pre 加参考图平方正则，matrix_suc 没有对应正则；本地此前修复参考参数共享存储，仅使已有的pre正则真实生效，没有添加新的约束。因此，suc方向存在可令图损失持续下降的负值方向；pre存在弱正则但仍明显漂移。这是从现有实现推出的机制，不等同于已证明作者全部实验存在同样问题。

初始背景行列为0，与官方构图时忽略背景的逻辑一致；但learnable=True使这些0仍可被训练更新，不能把初始为0误认为背景永久不参与。当前训练对所有帧计算图损失，包括占比较高的背景帧，容易推动背景列向负方向更新。

第50轮：pre约99.48%元素为负，suc全部为负；背景列均值分别为-16.78、-13.12，其他列均值分别为-6.52、-6.18。实际验证序列上，图修正平均给背景logit增加8.78，给其他类别平均增加3.48。由此背景获得明显额外优势，预测比例升到97.10%。这里只用均值描述整体偏移，不声称每帧均为相同加分。

## 排除与边界

- 累计进度改为当前进度不能挽救这次已训练权重的退化，故不是本轮主要直接原因；不意味着累计进度在重复动作中一定合理。
- 只清零背景行列仍低于raw，说明不能只修背景一列而忽略整个图的负值漂移。
- 初始图恢复性能但几乎不改变raw预测，不能据此证明任务图提高了骨架分割能力。
- 未因诊断结果重新选择测试权重或测试解码规则。原测试结果保留为既定协议结果。
